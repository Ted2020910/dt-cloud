# 以文件系统为多租户隔离层：tenant目录隔离+system共享

## 已知前提

- 003节点确定了抽象Agent接口层的设计
- 各种Agent（OpenClaw、Hermes、Claude Code）都基于本地文件系统工作
- 企业级平台需要：多租户隔离 + 企业级共享 + 团队级共享

## 认知起点

**核心洞察**：既然所有Agent都是基于本地文件系统的，那么**文件系统就是天然的多租户隔离层**，不需要额外的虚拟化或容器技术。

## 推导逻辑

**三层文件系统架构（v2 优化版）**：

```
/company-agent/
├── system/                        # 系统级共享（只读/管理员可写）
│   ├── skills/                    # 企业级Skill库（所有租户可用）
│   ├── knowledge/                 # 企业知识库（所有租户可读）
│   ├── templates/                # 工作流模板
│   └── policies/                  # 系统级策略（只读）
│
├── teams/                         # 团队级共享（团队成员可读写）
│   └── {team}/
│       ├── shared/               # 团队共享资源
│       │   ├── skills/           # 团队专属Skill
│       │   ├── knowledge/        # 团队知识库
│       │   └── templates/        # 团队工作流模板
│       ├── workspace/             # 团队工作区
│       └── policies/              # 团队级策略
│
└── tenants/                       # 租户隔离（每个员工独立）
    └── {user}/
        ├── workspace/            # 工作区（代码、文档等）
        ├── memory/                # 个人记忆（长期）
        ├── skills/                # 个人Skill（覆盖优先级：个人 > 团队 > system）
        ├── config/                # 个人配置
        ├── credentials/           # 密钥（加密存储）
        ├── traces/                # 操作审计日志
        └── .agent/                # Agent运行时
            ├── openclaw/         # OpenClaw配置
            ├── hermes/           # Hermes配置
            └── claude_code/      # Claude Code配置
```

**隔离级别说明**：

| 层级 | 路径 | 可见性 | 权限 | 示例 |
|------|------|--------|------|------|
| **System** | system/ | 所有租户 | 只读（管理员可写） | 企业Skill、知识库 |
| **Team** | teams/{team}/ | 团队成员 | 团队内读写 | 团队项目、经验 |
| **Tenant** | tenants/{user}/ | 仅本人 | 完全控制 | 个人记忆、工作 |

**Skill 覆盖机制**：

```
员工使用 Skill 的查找顺序（类似 Python import）：
1. tenants/{user}/skills/          # 个人Skill（优先级最高）
2. teams/{team}/shared/skills/     # 团队Skill
3. system/skills/                  # 企业级Skill
```

这样员工可以：
- 使用企业级通用Skill
- 使用团队专用Skill
- 创建个人Skill覆盖系统默认行为

⚠️ **覆盖策略**：个人 Skill 只在当前 tenant 生效，不会泄漏到团队或 system 级别。

**与Agent适配器的结合**：

```
Agent执行时的工作目录：
- OpenClaw → tenants/{user}/.agent/openclaw/
- Hermes   → tenants/{user}/.agent/hermes/
- Claude   → tenants/{user}/.agent/claude_code/

每个适配器只在自己的子目录操作，互不干扰
```

**v2 优化要点**（根据专家反馈）：
1. ✅ teams/{team} 下拆分 shared/workspace/policies，便于治理
2. ✅ tenants/{user} 下增加 credentials/traces/config
3. ✅ knowledge 与 embedding 索引分开管理（未来接入向量库）
4. ⚠️ 还需要：policy 文件明文定义、数据库级 tenant filter、sandbox 隔离

## 讨论共识

**架构决策**：

1. **以文件系统为隔离层**：简单、直接、利用现有Agent的工作方式
2. **三层结构**：system（系统共享）/ teams（团队共享）/ tenants（租户隔离）
3. **Skill覆盖机制**：个人 > 团队 > 企业，优先级清晰
4. **Agent配置隔离**：每个Agent有独立子目录，互不冲突

**优势**：
- 无需复杂的虚拟化或容器技术
- 直接复用Agent的本地文件系统工作方式
- 权限管理简单（操作系统级权限即可）
- 员工可以同时使用多个Agent，互不干扰
