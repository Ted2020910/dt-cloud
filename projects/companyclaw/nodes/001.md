# 公司级Agent平台：功能与架构定义

## 已知前提

- 员工目前在各自电脑上使用AI（本地部署的LLM或第三方API）
- 核心skills和知识以AI提示词、工作流、工具链的形式散落在员工本地
- 这些skills是公司的核心知识资产，不应随意外泄或复制
- 公司希望集中管控AI能力，同时保持员工的工作效率

## 认知起点

**核心问题重新定义：**

> 不是"如何让多agent帮人干活"，而是**"如何把散落在员工本地的核心skills集中到公司平台，实现可控共享、防止外泄"**

这改变了整个平台的定位：
- 从 **"个人AI工具"** → **"公司知识中枢"**
- 核心价值：**集中 + 保护 + 可控共享**

## 推导逻辑

**待讨论的核心问题：**

1. **知识集中化**：员工本地的skills如何迁移到平台？强制还是激励？
2. **访问控制**：skills谁可以看、谁可以用、谁可以修改？
3. **权限颗粒度**：按角色？按部门？按项目？
4. **使用场景**：员工在什么场景下会主动用平台而不是本地AI？
5. **平台边界**：平台只管skills，还是包含AI执行能力？
6. **技术架构**：中心化部署还是分布式？本地LLM还是API？
7. **迁移成本**：从现状迁移到新平台的阻力有多大？

## 讨论共识

**平台分为两层架构：**

**第一层：Agent运行平台（基础）**
- 员工在平台上使用agent完成任务
- 使用过程积累真实业务数据
- 数据驱动技能的迭代优化
- 第一层是**钩子**：吸引员工使用，建立迁移动力

**第二层：创造力释放平台（扩展）**
- 员工在第一层使用后发挥创造力
- 可以创建工具（Tools）
- 可以创建技能（Skills）
- 可以生成个人Memory
- 第二层是**复利**：员工创造 → skills沉淀 → 公司资产

**两层关系：**
```
第一层（Agent运行）
    ↓ 吸引员工使用 → 积累数据
第二层（创造力释放）
    ↓ 员工创造 → skills沉淀
公司知识资产（集中管控）
```

**核心价值逻辑：**
- 没有第一层 → 员工无动力迁移，skills继续散落
- 没有第二层 → 平台只是另一个本地AI工具
- 两层具备 → 员工用起来 + skills集中起来 + 数据积累起来

**未对齐问题（仍需讨论）：**
- 知识集中化方式：强制迁移还是激励迁移？
- 访问控制与权限颗粒度
- 平台边界（是否包含AI执行能力）
- 技术架构选型
