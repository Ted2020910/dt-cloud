# 开源项目调研：OpenClaw 不满足企业级多租户需求

## 已知前提

- 001节点定义了两层架构需求：第一层Agent执行平台 + 第二层Skill市场
- 搜索了多个开源项目：TigrimOS、OpenAgent、Dify、Coze、iflytek/skillhub、ClawHub
- 最终聚焦在 OpenClaw（因为用户提到"agent是指openclaw和claude code这样的"）

## 认知起点

**澄清"Agent"定义**：用户说的Agent是**工具型Agent**（OpenClaw、Claude Code），不是多智能体运行平台（LangGraph、AutoGen）。这改变了技术选型的方向。

## 推导逻辑

**OpenClaw 现有架构分析**：

```
OpenClaw 已有能力：
├── Agent 执行内核 ✅
├── Workspace 文件定义（Identity/Soul/Tools/Skills）✅
├── 四层记忆（Gateway/Agent Runtime/Skill系统/记忆）✅
├── ClawHub 技能市场（1700+ 技能）✅
└── Skill 管理命令（list/search/install/update/uninstall）✅

结论：OpenClaw 已完整实现两层架构，但只适合个人用户
```

**OpenClaw vs 企业级需求差距**：

| 企业级需求 | OpenClaw 现状 | 差距 |
|-----------|-------------|------|
| 员工独立 Memory | 只有 Agent 全局记忆 | ❌ 无用户级记忆 |
| 独立工作路径 | 共享 ~/.openclaw/workspace | ❌ 无数据隔离 |
| 多租户架构 | 单用户设计 | ❌ 不支持 |
| 权限管理（RBAC） | 无 | ❌ 不支持 |
| 团队 Skill 共享 | ClawHub（公开市场） | ⚠️ 无企业私有市场 |
| 审计日志 | 无 | ❌ 不支持 |

## 讨论共识

**结论：OpenClaw 不满足企业级需求，需要基于它二次开发**

**需要二次开发的核心模块**：

| 模块 | 开发方向 | 优先级 |
|------|---------|--------|
| 多租户隔离 | 用户认证 + 数据隔离（每人独立 storage） | P0 |
| 员工 Memory | 用户级记忆系统（独立于 Agent） | P0 |
| 权限管理 | RBAC（角色权限控制） | P0 |
| 企业 Skill 市场 | 私有 ClawHub（仅企业内部） | P1 |
| 审计日志 | 操作记录、异常监控 | P1 |
| 企业知识库 | 内部文档检索增强 | P2 |

**可借鉴 OpenClaw 的部分**：
- Skill 管理机制（install/search/list/update/uninstall）
- Workspace 架构思想
- ClawHub 的技能分类和分发模式

**架构方向**：以 OpenClaw 为 Agent 执行内核，上层叠加企业级多租户、能力！
