# Namespace 命名空间：知识库/向量库的多租户隔离与查询过滤

## 已知前提

- 004 节点定义了 system/knowledge、teams/{team}/knowledge、tenants/{user}/knowledge 三层
- 专家反馈：文件原文和 embedding 索引要分开管理，并强制按 namespace 隔离

## 认知起点

**问题**：
- 如果只做文件系统隔离，embedding 向量库（如 Weaviate、ChromaDB）查询时可能遗漏 tenant_id 过滤
- 知识检索泄漏 = 企业机密泄漏

## 推导逻辑

**Knowledge 三层存储模型**：

```
/company-agent/
├── system/
│   └── knowledge/
│       ├── raw/                  # 原始文档（PDF/MD/TXT）
│       │   ├── employee_handbook.pdf
│       │   └── coding_standards.md
│       └── embeddings/           # embedding 索引
│           └── chroma_db/
│               └── system_collection/
│
├── teams/
│   └── {team}/
│       └── knowledge/
│           ├── raw/
│           │   └── backend-design.md
│           └── embeddings/
│               └── chroma_db/
│                   └── team_{team}_collection/
│
└── tenants/
    └── {user}/
        └── knowledge/
            ├── raw/
            │   └── personal_notes.md
            └── embeddings/
                └── chroma_db/
                    └── tenant_{user}_collection/
```

**Namespace 隔离设计**：

| 层级 | Collection 命名 | Namespace 标记 |
|------|----------------|----------------|
| system | system_knowledge | namespace: "system" |
| team | team_{team_id}_knowledge | namespace: "team:{team_id}" |
| tenant | tenant_{user_id}_knowledge | namespace: "tenant:{user_id}" |

**查询时强制过滤**：

```python
class KnowledgeBase:
    def search(
        tenant_id: str,
        query: str,
        top_k: int = 5,
        scope: str = "all"  # "all" | "system" | "team" | "personal"
    ) -> list[SearchResult]:
        """知识检索，强制 tenant 隔离"""

        # 1. 构建 namespace 过滤器
        if scope == "all":
            namespaces = [
                f"tenant:{tenant_id}",
                f"team:{get_user_team(tenant_id)}",
                "system"
            ]
        elif scope == "personal":
            namespaces = [f"tenant:{tenant_id}"]
        # ... 其他 scope 处理

        # 2. 强制添加 tenant 过滤（防止遗漏）
        filters = {
            "namespace": {"$in": namespaces},
            "tenant_id": tenant_id  # 双重保险
        }

        # 3. 查询向量库
        results = self.vector_db.search(
            query=query,
            filter=filters,  # 强制过滤
            top_k=top_k
        )

        # 4. 二次验证（防止向量库 bug 导致泄漏）
        return self._verify_namespace(results, tenant_id)
```

**Embedding 与原文分离的好处**：

```
1. 独立备份策略
   - raw/ 文件：定期全量备份
   - embeddings/：可按需重建，成本低

2. 独立迁移
   - 用户离职时：删除 embeddings，不删 raw（保留企业知识）
   - 团队切换时：重建 embeddings 即可

3. 独立访问控制
   - raw/：依赖文件系统权限
   - embeddings/：依赖 namespace 过滤（双重保险）
```

## 讨论共识

**关键设计原则**：

1. **文件与索引分离**：raw/ 和 embeddings/ 分开管理
2. **强制 namespace 过滤**：查询时必须带 tenant_id 过滤
3. **双重保险**：文件系统权限 + 向量库 namespace 过滤
4. **可重建**：embedding 丢失可从 raw 重建

**与 Policy 联动**：

```yaml
# knowledge_access_policy.yaml
knowledge_retrieval:
  system_knowledge:
    retrievable_by: [all_tenants]
    scope: ["system"]

  team_knowledge:
    retrievable_by: [team_members]
    scope: ["team:{team_id}"]

  personal_knowledge:
    retrievable_by: [self]
    scope: ["tenant:{user_id}"]
```

**技术选型**：
- 向量库：ChromaDB（简单场景）、Weaviate（生产级）
- Embedding 模型：sentence-transformers（本地）或 OpenAI Embedding

**优先级**：P1（进阶功能），v1 可暂缓
