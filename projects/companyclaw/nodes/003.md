# 抽象Agent接口层：支持多底层实现自由切换

## 已知前提

- 001节点定义了两层架构需求
- 002节点调研了OpenClaw，确认其不满足企业级多租户需求
- 用户明确"Agent"指工具型Agent（OpenClaw、Claude Code、Hermes等）

## 认知起点

**架构思路转变**：

> 不是"基于某个Agent框架做二次开发"，而是**"做一个抽象层，兼容所有Agent实现"**

这解决了：
- 不用纠结选OpenClaw还是Hermes
- 不用等某个框架完善
- 用户可以按需选择、随时切换

## 推导逻辑

**核心设计：适配器模式**

```
┌─────────────────────────────────────────────────────┐
│           企业级 Agent 平台（统一入口）                │
│   每个员工有独立 Memory / 工作路径 / 权限 / Skill     │
├─────────────────────────────────────────────────────┤
│              Agent 抽象接口层                         │
│         (统一协议，适配任意 Agent)                    │
├─────────────────────────────────────────────────────┤
│  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌────────┐ │
│  │OpenClaw │  │Hermes   │  │Claude   │  │ 自定义  │ │
│  │ Adapter │  │ Adapter │  │Code适配 │  │ Adapter│ │
│  └─────────┘  └─────────┘  └─────────┘  └────────┘ │
└─────────────────────────────────────────────────────┘
```

**需要定义的标准接口**：

| 接口方法 | 说明 |
|---------|------|
| `execute(task)` | 执行任务 |
| `upload_skill(skill)` | 上传技能 |
| `list_skills()` | 列出可用技能 |
| `get_memory()` | 获取用户记忆 |
| `set_memory(memory)` | 设置用户记忆 |
| `get_workflow()` | 获取工作流配置 |

**每种Agent需要实现的Adapter**：
- `OpenClawAdapter` - 适配OpenClaw
- `HermesAdapter` - 适配Hermes
- `ClaudeCodeAdapter` - 适配Claude Code（如果支持）
- `CustomAdapter` - 自定义Agent适配

## 讨论共识

**架构决策**：

1. **平台定位**：企业级Agent平台，抽象Agent接口层，不绑定特定实现
2. **适配器机制**：每种Agent实现对应的Adapter，保持接口统一
3. **用户选择权**：用户可以自己选择使用哪个底层Agent
4. **切换能力**：支持在不同的Agent实现之间切换

**下一步**：
- 定义标准Agent接口（接口协议）
- 设计各Adapter的实现方案
- 确定优先级（先做哪个Adapter）
