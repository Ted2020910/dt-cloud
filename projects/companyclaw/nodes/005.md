# Policy 策略层：显式定义权限边界、覆盖规则和共享策略

## 已知前提

- 004 节点定义了 system/teams/tenants 三层文件系统结构
- 专家反馈：system 和 teams 的"可见但不可写"规则要明确写进 policy，否则技能覆盖、模板继承时会出现灰区

## 认知起点

**问题**：仅靠文件系统权限（r/w/x）无法表达"可见但不可写"之外的语义，例如：
- Skill 覆盖的优先级规则
- 跨层继承的可见性
- 操作类型的细粒度控制

## 推导逻辑

**Policy 文件结构**：

```
/company-agent/
├── system/
│   ├── policies/
│   │   ├── default.yaml          # 系统默认策略
│   │   ├── skills_policy.yaml   # Skill 可见性规则
│   │   └── access_control.yaml   # 跨层访问控制
│
├── teams/
│   └── {team}/
│       └── policies/
│           └── team_policy.yaml  # 团队级策略覆盖
│
└── tenants/
    └── {user}/
        └── policies/
            └── user_policy.yaml  # 个人策略覆盖
```

**Policy 语义示例（YAML）**：

```yaml
# system/policies/skills_policy.yaml
skill_visibility:
  system_skills:
    visible_to: [system, teams, tenants]
    editable_by: [system_admin]
    overridable: true              # 允许被下层覆盖

  team_skills:
    visible_to: [team_members]
    editable_by: [team_admin]
    overridable: false            # 不允许被下层覆盖

  personal_skills:
    visible_to: [self]
    editable_by: [self]
    overridable: false            # 只在当前 tenant 生效

override_rules:
  - name: "personal_skill_priority"
    condition: "skill_exists_in(tenant)"
    action: "use_tenant_version"
    scope: "skills"
```

**Policy 验证流程**：

```
Agent 请求 Skill X
    ↓
1. 检查 tenant/{user}/skills/ 中是否有 X
    ↓ 有 → 使用个人版本
    ↓ 无 → 继续
2. 检查 teams/{team}/shared/skills/ 中是否有 X
    ↓ 有 → 使用团队版本
    ↓ 无 → 继续
3. 检查 system/skills/ 中是否有 X
    ↓ 有 → 使用系统版本
    ↓ 无 → Skill Not Found
```

## 讨论共识

**关键设计原则**：

1. **显式优于隐式**：所有权限和可见性规则必须写进 policy 文件，不依赖文件系统权限的隐式推断
2. **覆盖有界**：Skill 覆盖只能在 tenant 层生效，不允许向上泄漏
3. **可审计**：Policy 变更记录在 traces/ 中
4. **默认安全**：未声明的权限默认拒绝
