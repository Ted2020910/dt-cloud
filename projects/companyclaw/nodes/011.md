# Multi-Agent vs Multi-Tenant：本质区别与OpenClaw能力边界

## 已知前提

- 用户最初提到 OpenClaw 时，误以为它支持多用户
- 需要澄清两个本质不同的概念

## 认知起点

**用户实际需求**：公司级别 Agent 平台，多个员工（30-50人）同时使用，每个员工有独立的数据和配置。

## 推导逻辑

### 概念对比

| 概念 | 定义 | OpenClaw 支持 | 示意图 |
|------|------|--------------|--------|
| **Multi-Agent** | 一个用户有多个专业 Agent（main/work/coding） | ✅ 完全支持 | 单用户，多 Agent |
| **Multi-Tenant** | 多个用户共享平台，数据隔离 | ❌ 不支持 | 多用户，数据隔离 |

### OpenClaw Multi-Agent 架构

```
~/.openclaw/
├── workspace/          # main agent 工作区
├── workspace-work/     # work agent 工作区
├── agents/
│   ├── main/sessions/  # main 会话
│   ├── work/sessions/ # work 会话
│   └── auth-profiles.json  # 认证（所有 agent 共享同一用户）
└── skills/            # 共享技能

结论：所有 Agent 都属于同一个用户，无用户隔离
```

### Multi-Tenant 架构（我们要的）

```
┌─────────────────────────────────────────┐
│           CompanyClaw Platform           │
├─────────────────────────────────────────┤
│  Alice (独立 memory、workspace、skills) │
│  Bob   (独立 memory、workspace、skills) │
│  Carol (独立 memory、workspace、skills) │
│                                         │
│  要求：Alice 无法访问 Bob 的数据        │
└─────────────────────────────────────────┘
```

### OpenClaw 不支持 Multi-Tenant 的原因

1. **无用户认证系统** - 没有登录机制
2. **无数据隔离** - 所有文件在同一用户目录下
3. **无权限控制** - 无法限制用户访问范围

### OpenClaw Multi-Agent 能力（可借鉴）

| 模块 | 借鉴价值 |
|------|----------|
| workspace 隔离结构 | 每个 Agent 独立目录 |
| sessions 管理 | 会话历史组织方式 |
| IDENTITY.md 模板 | Agent 身份定义格式 |
| bindings 路由 | 消息分发规则 |

## 讨论共识

1. **OpenClaw 支持 Multi-Agent（单用户多 Agent）**
2. **OpenClaw 不支持 Multi-Tenant（多用户数据隔离）**
3. **我们的需求是 Multi-Tenant**
4. **可借鉴 OpenClaw 的 Multi-Agent 架构设计**
