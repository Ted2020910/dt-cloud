# Traces 审计层：完整操作记录、异常检测和合规审计

## 已知前提

- 004 节点定义了 tenants/{user}/traces/ 目录
- 企业级平台需要满足合规审计需求

## 认知起点

**问题**：
- Agent 执行了哪些操作？
- 哪个 tenant 调用了敏感 Skill？
- 异常行为如何追溯？

## 推导逻辑

**Traces 目录结构**：

```
/company-agent/
├── system/
│   └── traces/
│       ├── audit.db              # 集中审计数据库
│       └── anomaly_alerts.json   # 异常告警记录
│
└── tenants/
    └── {user}/
        └── traces/
            ├── operations/       # 操作日志（结构化）
            │   ├── 2026-05-06.jsonl
            │   └── 2026-05-07.jsonl
            ├── skill_calls/      # Skill 调用详情
            │   └── {session_id}.jsonl
            ├── file_access/       # 文件操作记录
            │   └── {session_id}.jsonl
            └── errors/          # 异常记录
                └── {timestamp}.json
```

**Traces 数据模型**：

```json
// 操作日志条目示例
{
  "timestamp": "2026-05-06T14:30:00.123Z",
  "tenant_id": "alice",
  "agent_type": "openclaw",
  "session_id": "sess_abc123",
  "action": "skill_invoke",
  "skill_name": "code_review",
  "input": {
    "file": "/company-agent/tenants/alice/workspace/project/main.py"
  },
  "output": {
    "issues_found": 3,
    "severity": "medium"
  },
  "metadata": {
    "duration_ms": 1234,
    "model": "claude-sonnet-4"
  }
}
```

**异常检测规则**：

```yaml
# system/policies/audit_rules.yaml
anomaly_detection:
  - name: "excessive_file_deletion"
    condition: "file_delete_count > 50 in 1 hour"
    severity: "high"
    action: "alert_admin"

  - name: "sensitive_file_access"
    condition: "path matches ['/system/', '/teams/*/policies/']"
    severity: "medium"
    action: "log_audit"

  - name: "unknown_skill_execution"
    condition: "skill not_in [system_skills + team_skills + personal_skills]"
    severity: "high"
    action: "block_and_alert"
```

**审计日志查询接口**：

        """查询审计日志，支持多维度过滤"""

    def get_tenant_activity_summary(tenant_id: str) -> dict:
        """生成租户活动摘要，用于合规报告"""

## 讨论共识

**关键设计原则**：

1. **完整记录**：所有操作（Skill 调用、文件访问、API 请求）都记录
2. **结构化存储**：JSONL 格式便于查询和分析
3. **异常告警**：实时检测异常行为，触发告警
4. **合规导出**：支持生成合规报告（PDF/CSV）

**与 Credentials 的联动**：
- 密钥访问必须记录到 traces
- 配额耗尽时记录到 traces
- 异常访问时记录到 traces

**技术选型**：
- 日志存储：JSONL 文件 + SQLite 索引（简单场景）
- 高级场景：OpenTelemetry + Elasticsearch

**优先级**：P0（基础功能），必须实现
