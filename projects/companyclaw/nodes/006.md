# Credentials 密钥层：安全存储、多租户隔离和企业级密钥管理

## 已知前提

- 004 节点定义了 tenants/{user}/credentials/ 目录用于存储密钥
- 企业级 Agent 平台需要：API 密钥、模型配额、访问凭证等

## 认知起点

**问题**：如果密钥和配置混在一起：
- 密钥容易随配置文件泄漏（git commit 等）
- 无法统一管控预算和访问权限
- 审计时无法区分"谁用了多少次"

## 推导逻辑

**Credentials 目录结构**：

```
/company-agent/
├── system/
│   └── credentials/
│       ├── master_keyring        # 主密钥（加密存储，管理员可访问）
│       ├── model_api_keys/       # 系统级 API Key（Claude/DeepSeek等）
│       │   ├── claude_enterprise.yaml
│       │   └── deepseek_corporate.yaml
│       └── budget_policies.yaml  # 企业级预算分配
│
└── tenants/
    └── {user}/
        └── credentials/
            ├── personal_keyring  # 个人密钥（加密，仅本人可解密）
            ├── model_quota.yaml  # 个人配额限制
            └── usage_log.json    # 个人使用记录
```

**密钥管理设计**：

| 层级 | 内容 | 访问控制 |
|------|------|---------|
| system/credentials | 企业 API Key、主密钥 | system_admin 读写 |
| tenant/credentials | 个人 API Key、个人配置 | 租户本人 + system_admin 可读 |

**安全设计**：

```python
# 密钥访问接口
class CredentialStore:
    def get(self, tenant_id: str, key_name: str) -> str:
        """获取密钥，自动解密，触发审计日志"""
        # 1. 检查 tenant 是否有权访问此 key
        # 2. 从加密存储读取密文
        # 3. 用 tenant 私钥解密
        # 4. 记录访问日志到 traces/
        # 5. 返回明文（仅在内存中，不落盘）

    def set(self, tenant_id: str, key_name: str, value: str):
        """存储密钥，加密写入，触发审计日志"""
        # 1. 检查是否有写权限
        # 2. 用 system 公钥加密
        # 3. 写入 tenant 目录
        # 4. 记录变更日志
```

**与 Agent 适配器的集成**：

```
AgentAdapter 请求模型 API
    ↓
CredentialStore.get(tenant_id, "claude_api_key")
    ↓
验证 tenant 配额 → 返回密钥 → 调用模型
    ↓
记录到 traces/usage_log
```

## 讨论共识

**关键设计原则**：

1. **加密存储**：所有密钥明文不落盘，使用 tenant 私钥加密
2. **最小暴露**：Agent 只能通过 CredentialStore 接口获取密钥，不直接接触明文
3. **预算隔离**：每个 tenant 有独立配额，防止单一用户耗尽企业预算
4. **审计追溯**：每次密钥访问都记录到 traces/

**技术选型建议**：
- 密钥加密：age 或 SOPS
- 密钥管理：HashiCorp Vault（可选，企业级需求）
- 预算控制：结合 API 网关实现

**优先级**：P0（基础功能），必须实现
