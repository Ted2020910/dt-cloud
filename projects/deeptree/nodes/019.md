# 跨设备同步时的路径冲突——注册表如何区分不同机器

## 已知前提

- 全局注册表 `~/.dt/projects.json` 存储 `{ id, name, path, addedAt }`（节点 014 决策）
- `dt remote` 同步机制：本地 `.dt/` → `~/.dt/remote/projects/<id>/` → push 到 GitHub
- `remoteAutoSync` 通过 `path.dirname(dtRoot)` 反查注册表找 project-id
- 注册表会整体同步到云端 `registry.json`
- 实际场景：同一个人有多台电脑（公司/家/笔记本），同一项目在不同机器上路径不同

## 认知起点

核心矛盾：**项目 ID 是全局唯一的，但项目路径是设备绑定的。**

当 A 机器把 `registry.json` 推到云端后，B 机器拉下来，注册表里记录的是 A 机器的路径（如 `D:\personal-coding-projects\deeptree`），在 B 机器上这个路径可能是 `/home/user/code/deeptree`。

需要解决：
1. 云端注册表和本地注册表的关系是什么？
2. `dt remote clone` 拉下来的项目如何正确注册本地路径？
3. 如何避免 A 机器的路径覆盖 B 机器的路径？

## 推导逻辑

### 方案分析

**当前行为（有问题）：**
- `mergeRegistries()` 合并注册表时，远端新条目直接追加，保留远端的 path
- 这意味着 B 机器拉取后，注册表里会出现 A 机器的路径，指向不存在的目录
- `dt remote clone` 下载项目后会用本地路径注册，但如果只是 pull（非 clone）就不会修正

**关键洞察：注册表应该分层**

| 信息 | 归属 | 是否应该同步 |
|------|------|--------------|
| project-id | 项目 | ✅ 全局唯一标识 |
| project-name | 项目 | ✅ 显示名 |
| project-path | 设备 | ❌ 每台机器不同 |

**方案一：注册表拆分为云端+本地**

```
云端 registry.json:
  { id, name, createdAt }        ← 只存项目元信息

本地 ~/.dt/projects.json:
  { id, name, path, addedAt }    ← 存本机路径
```

合并策略：
- 从云端只拿 id/name（发现新项目用）
- 本机 path 永远以本地为准，云端不覆盖
- `dt remote clone` 时写入本机实际路径

**方案二：注册表加 device 字段**

```json
{
  "projects": [
    { "id": "deeptree", "name": "dt项目设计", "devices": {
      "DESKTOP-ABC": "D:\\personal-coding-projects\\deeptree",
      "MacBook-Pro": "/Users/xxx/code/deeptree"
    }}
  ]
}
```

优点：能看到所有设备的路径。缺点：暴露设备信息，结构复杂化。

**方案三：当前结构不变，合并策略修正**

保持 `{ id, name, path }` 结构，但修改 `mergeRegistries()`：
- 远端新项目追加时，path 设为空字符串或标记 `"<remote>"`
- 本地已有同 id 的项目，**永远保留本地 path 不被覆盖**
- 用户执行 `dt remote clone <id> <local-path>` 时才写入实际路径

### 推荐方向

方案三最小改动，方案一最干净。核心原则相同：**path 是本地数据，不参与云端同步。**

## 讨论共识

**用户决策：方案一——注册表拆分为云端+本地。**

设计：
- **云端 `registry.json`**：只存 `{ id, name, createdAt }` — 项目的全局元信息
- **本地 `~/.dt/projects.json`**：存 `{ id, name, path, addedAt }` — 包含本机路径
- 合并策略：从云端只同步 id/name（发现新项目），path 永远以本地为准
- `dt remote clone <id> <local-path>` 时写入本机实际路径

**需要的代码变更：**
1. `remoteAutoSync()` 推送时，`registry.json` 只写 `{ id, name, createdAt }`，剥离 path
2. `remotePullCurrent()` 拉取时，合并逻辑只用云端的 id/name 来发现新项目，不动本地 path
3. `mergeRegistries()` 修改：远端新条目追加时 path 为空，已有条目不覆盖 path
4. `dt remote list` 展示时：有本地 path 的显示路径，没有的标记为"未下载"
