# 统一格式的具体形状：代码里的答案

## 已知前提

已知统一格式应该围绕「角色 + 内容块（文本/工具调用/推理）+ token 用量」建模。协议差异（请求体结构、流式事件格式等）应当被隔离在统一层以下，不泄漏到统一格式中。

## 认知起点

`src/agents/stream-message-shared.ts` 是关键线索入口——它导入了来自 `@mariozechner/pi-ai` 的 `AssistantMessage`、`StopReason`、`Usage` 类型，并提供了构建这些对象的工厂函数。这说明统一格式的类型定义来自底层核心库，不是 OpenClaw 自己定义的。

## 推导逻辑

**线索一：`AssistantMessage` 的结构**

```typescript
// 来自 @mariozechner/pi-ai，OpenClaw 直接使用
type AssistantMessage = {
  role: "assistant";
  content: ContentBlock[];    // 内容块数组
  stopReason: StopReason;     // 停止原因
  api: string;                // 记录来自哪种协议
  provider: string;           // 记录来自哪个 provider
  model: string;              // 记录来自哪个模型
  usage: Usage;               // token 用量
  timestamp: number;
  responseId?: string;
  errorMessage?: string;
}
```

**线索二：`ContentBlock` 只有三种类型**

```typescript
// 三种类型覆盖了所有协议的输出差异
type ContentBlock =
  | { type: "text"; text: string }
  | { type: "thinking"; thinking: string; thinkingSignature: string; redacted?: boolean }
  | { type: "toolCall"; id: string; name: string; arguments: unknown }
```

`thinking` 块非常关键——Anthropic 的 `<thinking>` 标签和 OpenAI 的 `reasoning_effort` 输出是完全不同的原始格式，但最终都被规范化为同一个 `thinking` 块类型。

**线索三：`Usage` 统一了各家不同的计费字段**

```typescript
type Usage = {
  input: number;
  output: number;
  cacheRead: number;    // Anthropic 有 cache_read，OpenAI 有 cached_tokens，统一到这里
  cacheWrite: number;   // Anthropic 有 cache_creation，统一到这里
  totalTokens: number;
  cost: { input: number; output: number; cacheRead: number; cacheWrite: number; total: number };
}
```

**值得注意的设计决策**：`AssistantMessage` 保留了 `api`、`provider`、`model` 三个字段。这不是为了让上层代码做条件分支——而是为了**调试、日志和跨模型历史回放**时能追溯消息来源。当对话历史里混有来自不同模型的消息时（切换模型场景），需要知道每条消息的原始来源，才能正确处理 `thinking` 块的 `thinkingSignature`（见 `transport-message-transform.ts`）。

## 讨论共识

统一格式的三层结构已经清晰：

```
AssistantMessage
  ├─ 元数据层：api / provider / model / stopReason / timestamp
  ├─ 内容层：ContentBlock[]（text / thinking / toolCall）
  └─ 用量层：Usage（input / output / cacheRead / cacheWrite / cost）
```

这个格式完整覆盖了 003 节点识别出的「公约数」，同时把各协议的差异全部收进了 `ContentBlock` 的三种类型里。**它来自底层库 `@mariozechner/pi-ai`，不是 OpenClaw 自己定义的**——这意味着多项目之间共享了这套统一契约。
